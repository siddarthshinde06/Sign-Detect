# SignSense — Real-Time Hand Sign Detection

SignSense is a real-time hand sign / gesture recognition system. It uses **MediaPipe** to extract 21 hand landmarks from a webcam feed, feeds normalized landmark coordinates into a trained **SVM classifier**, and shows the predicted sign live in a browser dashboard.

The project has two parts:

1. **Detection app** (`app.py` + `static/`) — a FastAPI backend that streams your webcam to a web UI and overlays the predicted sign in real time. This is the "run it and use it" part — it expects a model that's already been trained.
2. **Data collection & training tool** (`CollectEvalute.py`) — a standalone Tkinter desktop app for recording your own gesture dataset, training the SVM model on it, and evaluating accuracy. Run this first if you don't already have `svm_model.pkl` and `scaler.pkl`.

## How it works

Every frame goes through the same pipeline in both scripts, so a model trained with `CollectEvalute.py` works directly with `app.py`:

1. **MediaPipe Hands** detects one hand and returns 21 (x, y, z) landmarks.
2. **Normalization** — every landmark is made relative to the wrist (landmark 0), then scaled by the wrist-to-middle-MCP (landmark 9) distance. This makes the features roughly invariant to hand position and distance from the camera.
3. **Feature vector** — the normalized landmarks are flattened into a 63-value vector (21 × 3).
4. **Scaling** — a fitted `StandardScaler` transforms the vector.
5. **Classification** — an `SVC(kernel='rbf', probability=True)` predicts a label and confidence.
6. **Smoothing** — predictions are buffered over the last 5 frames; the majority label is shown only if its average confidence is ≥ 0.8, otherwise the UI shows "Low Confidence."

## Project structure

```
.
├── app.py                # FastAPI backend — real-time detection + web UI server
├── CollectEvalute.py      # Tkinter app — data collection, training, evaluation
├── static/
│   ├── index.html          # Web dashboard
│   ├── script.js            # Frontend logic (start/stop, polling, status)
│   └── style.css             # Dashboard styling
├── svm_model.pkl          # Trained SVM model (generated by CollectEvalute.py)
├── scaler.pkl              # Fitted StandardScaler (generated by CollectEvalute.py)
└── dataset.csv            # Collected landmark data with labels (generated by CollectEvalute.py)
```

> **Note:** `app.py` expects `index.html`, `script.js`, and `style.css` to live inside a `static/` folder next to it, and `svm_model.pkl` / `scaler.pkl` to live directly next to it. It will refuse to start if the `static/` folder is missing, and detection will report "no model found" until both `.pkl` files are present.

- Python 3.9+


## Usage

### 1. Collect training data and train a model

If you don't already have `svm_model.pkl` and `scaler.pkl`, run:

```bash
python CollectEvalute.py
```

This opens a desktop app with four tabs:

- **Data Collection** — enter a gesture label (e.g. `A`, `Hello`) and a target sample count, then show the gesture to your webcam. Each captured frame is stored 3× (original, horizontally mirrored, and with small random noise added) to help the model generalize. Data is appended to `dataset.csv`.
- **Model Training** — runs a grid search (`C` × `gamma`) over an RBF-kernel SVM with 5-fold cross-validation, then saves the best model as `svm_model.pkl` and the fitted scaler as `scaler.pkl`. Reports accuracy and a confusion matrix.
- **Real-Time Prediction** — a quick OpenCV preview window to sanity-check the trained model before deploying it.
- **Settings & Stats** — view class distribution in `dataset.csv`, clear the dataset, or export a results summary.

Repeat data collection for each gesture you want the model to recognize before training.

### 2. Run the live detector

Once `svm_model.pkl` and `scaler.pkl` exist next to `app.py`:

```bash
python app.py
```

Then open the app in your browser:

```bash
http://localhost:8000
```

Click **Start Detection** to open the webcam feed; the predicted sign and confidence appear below the video. **Reload Model** re-loads the `.pkl` files without restarting the server (useful after retraining). **Stop** releases the camera.

## API reference

`app.py` exposes a small JSON API alongside the static frontend:

| Method | Endpoint            | Description                                          |
|--------|----------------------|-------------------------------------------------------|
| POST   | `/api/start`         | Opens the camera and starts detection                 |
| POST   | `/api/stop`          | Stops detection and releases the camera                |
| POST   | `/api/reload_model`  | Reloads `svm_model.pkl` / `scaler.pkl` from disk        |
| GET    | `/api/status`        | Current state: running, model status, last prediction, hand-detected flag |
| GET    | `/video_feed`        | MJPEG stream of the annotated camera feed (only while running) |

## Notes & limitations

- Only **one hand** is tracked at a time (`max_num_hands=1`).
- The camera-opening logic tries platform-specific backends first (DirectShow/MSMF on Windows, AVFoundation on macOS, V4L2 on Linux) and falls back to the default, retrying briefly before giving up.
- Predictions need 5 consecutive frames to stabilize before anything is shown, and a confidence below 0.8 is deliberately displayed as "Low Confidence" rather than a guess.
- Recognition quality depends entirely on the quantity and variety of gestures recorded in `CollectEvalute.py` — more samples per label, and more variation in hand angle/lighting, will noticeably improve accuracy.
